- **p50/p95/p99 无法独立重算**：`bench_http`/`bench_stress` 只落盘聚合分位数，逐请求原始样本未持久化。→ 8.8 修复项。
- **今天 0 个真正的 HTTP 504。** 过载失败的实际形态是 **200 + 空响应体 / ReadError**，不是干净 504。
- 可核验项全部对得上（差异为 0）：各档 failures（stdout 计数 == JSON 字段）、分位数单调性、JSON→SUMMARY 转写、stress 重建 == stdout。

## 复习讲透的 5 个点

1. **p95**：升序排好后取第 95% 位置的值（inclusive 插值），描述尾巴；样本少时 p95/p99 贴近 max、很抖。
2. **TTFA ≈ total**：说明 qwen3 是 emulated streaming（先合成完整音频再切片发），不是真增量流式——用户先静等 RTF×音频时长。
3. **c=8 大面积失败不算测错**：是真实容量拐点；但失败以空体/断连而非 504 出现，是服务端过载语义的设计缺陷。
4. **RTF≈1.5**：纯模型效率（gpu_smoke 测，无排队）；bench_http 在高并发的 RTF 被排队放大（c=4→5.8）。单条 20–30s = 音频时长(16s) × RTF(1.5)。
5. **cancel 证据看服务端不看客户端**（概念）：三样——服务端日志的 GeneratorExit/CancelledError、GPU util 回落、metrics 里取消不计失败/不计延迟。

## 8.8 补测清单

**A. 没跑 / 跑错的档（最优先）**
1. cancel 压测（c=4 混合 30% 断开 vs 纯净 c=4）——今天完全没跑。
2. stress 重跑：加 `--texts-file`，用英文数据集（今天用了默认中文短文本，不可比）。
3. WebSocket 流式矩阵——原计划有，今天只测了 HTTP。

**B. 满屏失败的档（c=4 / c=8）——先修再重测**
4. 修服务端过载语义：过载走干净 504（而非 200-空体/ReadError），让 120s<180s 设计生效、失败可按 504 分类。
5. 落盘逐请求 raw samples，使 p95/p99 可独立复核。
6. 每档样本量 ≥200（50 条算 p99 太抖，c=4 p99≈max）。

**C. 优化 A/B**
7. 装 flash-attn（最大杠杆）：RTF 1.5 → 可能 <1，单条 20–30s → ~10s，并发上限可能上移。同文本同并发 on/off 对比。
8. （可选）批处理 / 更小模型 / 真增量流式。
